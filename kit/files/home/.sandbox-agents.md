# Sandbox environment

OpenCode sandbox: outbound traffic goes through a deny-by-default proxy firewall, and GitHub
credentials are injected at the network level — push and open PRs directly from inside the sandbox.

## Guidance files

Use based on your task:

- **[Persistent shell environment](~/.sandbox-agents/persistent-env.md)** — `/etc/sandbox-persistent.sh`
  mechanism, tool-init rules, the completion-scripts hazard, the login-shell PATH trick. Read when
  installing tools, persisting env vars, or when bash commands silently return no output.
- **[Network access](~/.sandbox-agents/network.md)** — HTTP 403 block shapes and `sbx policy`
  commands, IP-stack connection failures, port publishing, `host.docker.internal`, the Aspire
  `[::1]` fix. Read when requests are blocked or fail, when a service must be reachable from the
  host, or when Aspire returns 502s.
- **[Git authentication](~/.sandbox-agents/git-auth.md)** — proxy-injected credentials, push/PR
  workflow, `sbx secret set github` recovery. Read when git push fails with auth errors or before
  pushing and opening PRs.
- **[Git workspace mode](~/.sandbox-agents/workspace-mode.md)** — direct vs clone mode, where
  commits live, fetching host commits. Read before reasoning about how your changes reach the host.

## Environment facts

- Outbound network is deny-by-default; blocked requests return HTTP 403 with a structured body.
- `/etc/sandbox-persistent.sh` is sourced before every bash invocation — persist tool setup there,
  never shell completions.
- `gh auth status` showing "not logged in" is expected; HTTPS Git auth is proxy-injected.
- Workspace mode check: `if [ -d /run/sandbox/source ]; then echo "clone mode"; else echo "direct mode"; fi`
- sudo is available for installing packages; npm, pip, and uv are preinstalled.
